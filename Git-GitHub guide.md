1. Настройка (делается один раз)

```bash
git config --global user.name "Твое Имя"
git config --global user.email "tvoya@pochta.ru"
```

2. Старт проекта

Создать новый репозиторий или скопировать чужой.

```bash
git init            # Создать новый пустой репозиторий в текущей папке
git clone [url]     # Скачать готовый проект (например, с GitHub)
```

3. Сохраняем изменения (Commit)

Главный цикл работы: изменить -> добавить в корзину -> упаковать.

```bash
git status                  # Посмотреть, что изменилось (красным списком)
git add [файл]             # Добавить конкретный файл в "корзину"
git add .                  # Добавить все измененные файлы разом
git commit -m "Сообщение"  # Упаковать корзину в коммит (снапшот)
git log                    # Посмотреть историю коммитов (выйти - клавиша Q)
```

4. Работа с ветками

Ветки нужны, чтобы не сломать основную версию (main/master).

```bash
git branch                 # Показать список веток (* где мы сейчас)
git branch [имя]          # Создать новую ветку
git checkout [имя]        # Переключиться на другую ветку
git checkout -b [имя]     # Создать новую ветку И сразу переключиться
git merge [имя]           # Влить ветку [имя] в текущую ветку (из мастер-ветки)
git branch -d [имя]       # Удалить ветку
```

5. Синхронизация с интернетом (GitHub/GitLab)

Общение с удаленным сервером (origin).

```bash
git push                 # Отправить свои коммиты на сервер
git pull                 # Скачать новые коммиты с сервера к себе
git remote add origin [url] # Привязать локальную папку к репозиторию в облаке
```

6. "Откаты" и срочные исправления
Если вы ошиблись.

```bash
git restore [файл]       # Отменить изменения в файле (если еще не добавили в git add)
git reset HEAD [файл]    # Убрать файл из "корзины" (передумали коммитить)
git reset --hard HEAD   # Жесткий откат: удалить все изменения до последнего коммита (осторожно!)
git diff                 # Показать построчно, что именно изменилось в файлах
```
